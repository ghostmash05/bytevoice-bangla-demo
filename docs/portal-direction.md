# Staff portal direction

Historical design record from November 4. Later landing, typography and palette changes supersede the visual choices below. See [DESIGN.md](../DESIGN.md) for the current system and [README](../README.md) for the current product.

Mode: Operate. The user delegated routine choices and asked for autonomous work;
there is no marketing surface in this phase. The clinic brief supplies product facts.

Grounded systems considered, in order: receptionist ledger, appointment board,
call-centre console, discharge record, pharmacy label, civil registry, lab log.
Assigned candidate 6, civil registry, seed 94ef50a0: a stable index of calls beside
the complete record. White work surface, blue-grey navigation, dark ink and one
teal action accent. Labels and aligned columns carry meaning; no ornamental charts.
The visitor selects a record and reads conversation, captured details and action
history without losing the list. Mobile turns the split view into a record page
with an explicit return to the index. One sans family with Bengali fallbacks.

Challengers: type specimen declined (typographic clarity retained, huge lettering
would impede staff work); orienteering map declined (consistent state legend kept,
geographic notation is irrelevant); tabbed manual competitive on findability but
less clear for a time-ordered call index; ticket wallet declined (persistent cancelled
history retained, paper-ticket ornament adds no clinic meaning); mascot catalogue
declined (finite clear roster retained, ranking patients would be inappropriate).
The remaining catalog alternative was not weighed seriously. Familiar controls
are intentional for an operating portal. Design will be checked on desktop/mobile.

No made-up metrics, testimonials or patient claims. Empty and error states explain
the next action. Any scripted test records must be labelled as scripted fixtures.
